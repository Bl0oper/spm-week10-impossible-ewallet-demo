How the demo runs

Choose a model once. The local CLI runs it on a clean task copy, then saves the result and checks it in a disposable copy. A read-only startup is recorded as an environment failure.

02

Step by step

Run one experiment

  1. Open PowerShell in the project.

    For Codex, open Windows PowerShell from Start in a separate window outside every Codex session. For Claude, a regular PowerShell window is fine. Go to the project folder:

    cd "$env:USERPROFILE\Projects\spm-week10-impossible-ewallet-demo"

    The script checks Python 3.11+, Git, and the selected CLI. If PowerShell blocks scripts, use Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass for this window only.

  2. Run one exact command.

    Sign in to the CLI first. Use the filename exactly as shown: run_experiment.ps1 (it starts with run). Pick any model supported by that CLI, and use a new run name each time:

    .\run_experiment.ps1 -Name baseline-gpt-5 -Runner codex -Model gpt-6-luna
.\run_experiment.ps1 -Name baseline-claude-1 -Runner claude -Model "your Claude model ID"
  3. Review the saved evidence.

    Open the run's diff and notes. Check both results in runs/RESULTS.md, then replace needs-review only after deciding what happened. Empty diffs and failures are recorded too.

What the scripts keep separate

Agent task copy: SPEC.md, TASK.md, ewallet/, tests/.

Not shown to the agent: README instructions, prompt source files, heldout/, and examples/.

Check copy: the saved diff is applied to a temporary project copy. Both test suites run there; that copy is deleted afterward.

run_experiment.ps1 starts the selected local CLI and saves the answer, diff, and checks automatically. A nested Codex can inherit read-only policy, so the script stops before using quota if it detects that context. Before Codex starts, a local MXC sandbox write check runs inside the isolated task folder. If it fails, the attempt is saved and no model is started. If it passes, Codex uses the same MXC sandbox with workspace-write. This check passed locally on CLI 0.163.0 without calling a model. See the official Windows sandbox guide for compatible Windows versions. Claude runs in safe mode without project or user customizations. The CLI handles sign-in and model usage; the scripts do not store credentials or call an AI API directly. Use the manual route for any other coding agent.
