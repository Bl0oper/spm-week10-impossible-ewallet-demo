01

How the demo runs

Choose a model once. The local CLI runs it on a clean task copy, then saves the result and checks it in a disposable copy. A read-only startup is recorded as an environment failure.

02

Step by step

Run one experiment

  1. Open PowerShell in the project.

    Check Python with py --version and Git with git --version. If PowerShell blocks scripts, use Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass for this window only.

  2. Run exactly one command.

    Sign in to Codex or Claude Code first, then choose any model accepted by that CLI. Use one line per experiment and a new run name each time:

    .\run_experiment.ps1 -Name baseline-gpt-1 -Runner codex -Model "your GPT model ID"
.\run_experiment.ps1 -Name baseline-claude-1 -Runner claude -Model "your Claude model ID"
  3. Review the saved evidence.

    Open the run's diff and notes. Check both results in runs/RESULTS.md, then replace needs-review only after deciding what happened. Empty diffs and failures are recorded too.

What the scripts keep separate

Agent task copy: SPEC.md, TASK.md, ewallet/, tests/.

Not shown to the agent: README instructions, prompt source files, heldout/, and examples/.

Check copy: the saved diff is applied to a temporary project copy. Both test suites run there; that copy is deleted afterward.

run_experiment.ps1 starts the selected local CLI. Open Windows PowerShell from Start for Codex; a nested Codex can inherit read-only policy, and the script stops early when it detects that context. Codex ignores user config and requests workspace-write; confirm its startup summary says sandbox: workspace-write. If it says read-only, keep the attempt in the log and stop: no code result was produced. This happened twice, including once when the launcher requested workspace-write; the cause remains unknown. Claude runs in safe mode without project or user customizations. The CLI handles sign-in and model usage; the scripts do not store credentials or call an AI API directly.
